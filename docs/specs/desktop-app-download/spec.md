# 데스크톱 앱으로 설치하고 웹에서 내려받기

My Claude Inspector를 Windows x64 데스크톱 앱으로 만든다. 교육생은 https://myclaudeinspector.vercel.app/download 에서 최신 설치 파일을 내려받아 설치하고, 시작 메뉴에서 연다. 창을 닫아도 트레이에 남아 정해 둔 주기로 현황을 새로 읽는다. 이 단계의 앱은 PC 밖으로 아무것도 보내지 않는다. 로그인과 랭킹 업로드는 `docs/specs/desktop-ranking-sync/`가 이어서 맡는다.

연결된 자료:
- [prototype.html](prototype.html) — 승인된 화면. 이 폴더가 따르는 화면과 상태는 다음과 같다.
  - **다운로드 (웹):** 기본 상태와 "배포된 버전 없음" 상태
  - **대시보드 머리말:** 앱 메뉴(대시보드·트렌드·설정)와 마지막·다음 업데이트 시각
  - **설정 화면의 "업데이트" 카드:** 업데이트 주기, Windows를 켤 때 실행, 창을 닫으면·트레이 메뉴 미리 보기
  - 같은 파일의 로그인, 랭킹, 설정의 "계정과 랭킹" 카드, 머리말의 "랭킹 참여 중" 표시는 desktop-ranking-sync가 따르는 부분이라 이 폴더에서는 만들지 않는다.
  - 대시보드·트렌드·자세히 보기 화면 자체는 이미 출시된 그대로다. 데이터는 모두 예시다.
- [PRODUCT.md](../../../PRODUCT.md) — PC에서 데스크톱 앱으로 동작, 읽기 전용, 비밀 값은 읽지 않음, 업데이트 주기는 사용자가 정함.
- [ui-composition](../../decisions/ui-composition.md) — 일반 UI는 공식 shadcn component로 구성하고 색은 semantic token으로만 표현한다.
- [claude-status-dashboard](../claude-status-dashboard/spec.md) — 이미 출시된 대시보드·트렌드·자세히 보기와 Claude Style. 이 작업은 그 동작을 바꾸지 않는다.

## 사용자에게 보이는 결과

1. 교육생이 https://myclaudeinspector.vercel.app/download 에서 "Windows용 다운로드"를 눌러 최신 설치 파일을 받는다. 버전, 날짜, 크기, 지원 Windows, 설치 방법, 앱이 하는 일이 같은 페이지에 있다.
2. 설치 파일을 실행하면 앱이 설치되고 시작 메뉴에 생긴다. Node.js나 bun을 따로 설치하지 않아도 된다.
3. 앱에서 대시보드, 트렌드, 자세히 보기를 지금 웹앱과 같은 값으로 본다. 위쪽 앱 메뉴로 대시보드, 트렌드, 설정을 오간다.
4. 창을 닫아도 트레이에 남아, 정해 둔 주기마다 현황을 새로 읽고 그날 스냅샷을 갱신한다. 트레이 메뉴의 "종료"로 완전히 끈다.
5. 설정에서 업데이트 주기와 Windows 시작 시 실행을 바꾼다.
6. 새 버전이 나오면 다운로드 페이지가 저절로 그 버전을 가리킨다.

## 승인된 범위

- Windows x64용 Electron 설치 파일(`setup.exe`). 시작 메뉴 등록과 제거 프로그램 포함.
- 버전마다 설치 파일을 이 저장소의 GitHub Releases에 올리는 배포 흐름
- 웹 다운로드 페이지(`/download`): 최신 버전 정보와 다운로드 버튼, 릴리스 노트·이전 버전 링크, 설치 방법(SmartScreen 경고 넘기는 법 포함), 이 앱이 하는 일, 배포된 버전이 없을 때 안내
- 앱 메뉴(대시보드·트렌드·설정)와 대시보드 머리말의 마지막·다음 업데이트 시각
- 트레이 아이콘과 메뉴(열기, 지금 업데이트, 다음 업데이트 시각, 종료), 창을 닫으면 트레이로 숨기기
- 주기 업데이트(PC 화면 새로 읽기와 스냅샷 갱신)
- 설정 화면의 "업데이트" 카드: 업데이트 주기, Windows를 켤 때 실행, 창을 닫을 때 동작 안내

## 수용 기준

**내려받기**
- AC1. https://myclaudeinspector.vercel.app/download 에 이 저장소 GitHub Releases의 최신 버전 번호, 날짜, 설치 파일 크기, "Windows 10·11 (64비트)"가 보인다. "Windows용 다운로드"를 누르면 그 버전의 설치 파일이 내려받아진다.
- AC2. 새 버전을 GitHub Releases에 올리면 다운로드 페이지를 다시 배포하지 않아도 1시간 안에 새 버전을 가리킨다.
- AC3. 다운로드 페이지에 릴리스 노트와 이전 버전 목록 링크, 설치 방법 4단계(실행 → "추가 정보 → 실행" → 시작 메뉴에서 열기 → 제거 방법), 이 앱이 하는 일(읽기만 함, PC 밖으로 보내지 않음, 트레이에서 주기 업데이트)이 있다.
- AC4. GitHub Releases에 올린 버전이 없거나 정보를 받아 오지 못하면 "아직 배포된 버전이 없어요" 안내가 보이고, 깨진 다운로드 버튼은 보이지 않는다.
- AC5. 웹 첫 화면(`/`)에서 다운로드 페이지로 가는 링크가 보인다.

**설치와 실행**
- AC6. Node.js·bun이 없는 Windows x64 PC에서 내려받은 설치 파일을 실행하면 앱이 설치되고 시작 메뉴에 "My Claude Inspector"가 생긴다. 제거 프로그램으로 지울 수 있다.
- AC7. 설치한 앱에서 대시보드, 트렌드, 자세히 보기가 지금 웹앱과 같은 값과 동작으로 보인다(claude-status-dashboard의 수용 기준 유지). Claude 설치 경로 기본값은 그 PC 사용자의 `~/.claude`이고, 마지막으로 넣은 프로젝트 경로는 다음 실행 때 다시 채워진다.
- AC8. 앱 위쪽 메뉴로 대시보드, 트렌드, 설정을 오가고, 지금 화면이 메뉴에 표시된다.
- AC9. 앱은 PC 밖으로 아무 요청도 보내지 않는다. 자세히 보기의 강의 그림과 링크처럼 사용자가 여는 강의 자료는 예외다.

**트레이와 주기 업데이트**
- AC10. 창을 닫으면 앱이 끝나지 않고 트레이 아이콘으로 남는다. 트레이 메뉴에 "My Claude Inspector 열기", "지금 업데이트", 다음 업데이트 시각, "종료"가 있다. "종료"를 고르면 앱과 업데이트가 모두 멈춘다.
- AC11. 설정의 업데이트 주기(15분, 30분, 1시간, 3시간, 하루)마다 현황을 새로 읽고 그날 스냅샷을 갱신한다. 대시보드 머리말에 마지막·다음 업데이트 시각과 주기가 보인다.
- AC12. 트레이 메뉴의 "지금 업데이트"를 누르면 주기를 기다리지 않고 바로 업데이트하고, 다음 업데이트 시각을 그때부터 다시 센다.
- AC13. "Windows를 켤 때 실행"을 켜면 Windows에 로그인할 때 앱이 트레이로 시작하고, 끄면 시작하지 않는다.
- AC14. 앱을 두 번 실행하면 새 창을 더 띄우지 않고 이미 떠 있는 창을 앞으로 가져온다.

**경계**
- AC15. 앱은 Claude 설정 파일을 바꾸지 않고, 로그인 정보·토큰·API 키 같은 Claude 쪽 비밀 값을 읽지 않는다.
- AC16. 앱 창과 다운로드 페이지는 넓은 화면, 768px, 390px 폭에서 가로로 넘치지 않는다.

## 확정된 제약과 근거

- **Windows x64용 Electron 설치 파일로 배포한다.** 지금 앱이 PC 파일을 읽는 Node.js 서버를 함께 실어야 하고, 트레이·백그라운드 실행·시작 시 실행을 기본으로 지원하기 때문이다. 단일 exe는 실행마다 풀어서 느리고 시작 시 실행과 잘 맞지 않는다. (사용자 확정)
  - Electron과 electron-builder에는 공식 에이전트 스킬이나 `llms.txt`가 없다(2026-11-19 확인: skills.sh 검색, electronjs.org·electron.build `llms.txt` 404). 공식 문서는 구현할 때 직접 확인한다. 커뮤니티 스킬 `pedronauck/skills@electron-builder`, `full-stack-skills/electron-skills`는 설치하지 않았다.
- **창을 닫으면 트레이에 남아 업데이트를 계속하고, 트레이 메뉴의 "종료"로만 멈춘다.** (사용자 확정)
- **설치 파일은 GitHub Releases에 올리고, Vercel의 `/download` 페이지는 최신 릴리스를 가리킨다.** 설치 파일이 150–250MB인데 Vercel 업로드 한도는 Hobby 100MB이고(https://vercel.com/docs/limits "Static file uploads", 2026-11-19 확인), GitHub 저장소도 100MB가 넘는 파일을 받지 않기 때문이다. (사용자 확정)
- **데스크톱 앱과 내려받기를 랭킹 연동보다 먼저 낸다.** 랭킹 연동은 랭킹 서버의 삭제 API를 기다리고 있어서다. (사용자 확정)

## 가정 (바꿀 수 있음)

- 업데이트 주기 선택지는 15분, 30분, 1시간, 3시간, 하루이고 기본값은 1시간이다.
- "Windows를 켤 때 실행"의 기본값은 꺼짐이다.
- 첫 버전 번호는 `0.1.0`이고, 설치 파일 이름은 `MyClaudeInspector-Setup-<버전>.exe`다.
- 다운로드 페이지는 GitHub Releases의 최신 릴리스 정보를 1시간마다 새로 읽는다.
- 앱 안의 설정 화면은 이 단계에서 "업데이트" 카드만 있다. "계정과 랭킹" 카드는 desktop-ranking-sync가 더한다.
- 앱의 대시보드 머리말에는 "트렌드 보기" 버튼 대신 위쪽 앱 메뉴를 쓴다. 웹에서 여는 기존 대시보드는 지금 모양을 유지한다.

## 범위 밖과 이유

- **로그인, 랭킹 업로드, 랭킹 화면, 기록 삭제:** `docs/specs/desktop-ranking-sync/`가 맡는다.
- **macOS·Linux 설치 파일, 코드 서명, 앱 안 자동 업데이트:** 요청되지 않았다. 새 버전은 다운로드 페이지에서 다시 받아 설치한다.
- **설치 파일을 Vercel이나 저장소에 직접 두는 것:** 위 크기 한도 때문에 할 수 없다.
- **보안 하드닝, 엣지케이스·성능 방어:** AGENTS.md의 검증·리뷰 예산에 따라 범위 밖이다.

## 남은 위험

- **서명 없는 설치 파일:** Windows SmartScreen이 "알 수 없는 게시자" 경고를 띄운다. 다운로드 페이지의 설치 방법 2단계가 이를 안내한다. 회사 PC처럼 정책으로 막힌 곳에서는 설치하지 못할 수 있다.
- **설치 파일 크기:** Chromium과 Node.js가 함께 들어가 150–250MB 정도다. 지금 빌드는 스냅샷 폴더를 읽는 코드 때문에 프로젝트 전체를 서버 출력에 넣으려는 경고가 있어, 정리하지 않으면 더 커진다.
- **GitHub API 호출 한도:** 다운로드 페이지가 최신 릴리스 정보를 받을 때 GitHub API를 쓴다. 한도에 걸리면 AC4의 안내가 보인다.
- **PC를 끄거나 앱을 종료한 동안:** 주기 업데이트가 멈춰서 그날 스냅샷이 비는 날이 생긴다.
