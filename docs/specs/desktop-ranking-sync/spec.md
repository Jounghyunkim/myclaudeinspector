# 데스크톱 앱과 선택형 사용량 랭킹 연동

My Claude Inspector를 Windows 데스크톱 앱으로 설치해 쓰게 한다. 원하는 사람은 로그인해서, 자기가 정한 주기마다 날짜별 사용 숫자를 랭킹 서버에 올리고, 다른 교육생과 순위를 비교하고, 올린 기록을 직접 지울 수 있다.

연결된 자료:
- [prototype.html](prototype.html) — 승인된 화면. 로그인, 랭킹, 설정 화면과 대시보드 머리말의 앱 메뉴·업데이트 상태, 그리고 각 상태(로그인 실패, 처음 로그인, 로그인 안 함, 업로드 실패, 삭제 확인)의 배치와 문구는 이 파일을 따른다. 대시보드·트렌드·자세히 보기 화면 자체는 이미 출시된 그대로이고, 이 파일에 함께 들어 있을 뿐이다. 데이터는 모두 예시다.
- [PRODUCT.md](../../../PRODUCT.md) — 랭킹 참여는 선택, 숫자와 이름까지만 올림, 대화 내용·CLAUDE.md·Memory 본문 제외, 비밀 값은 읽지 않음, 본인 삭제, 사용자가 정한 업데이트 주기.
- [ui-composition](../../decisions/ui-composition.md) — 일반 UI는 공식 shadcn component로 구성하고 색은 semantic token으로만 표현한다.
- [claude-status-dashboard](../claude-status-dashboard/spec.md) — 이미 출시된 대시보드·트렌드·자세히 보기와 Claude Style. 이 작업은 그 동작을 바꾸지 않는다.

선행 조건: 다른 worktree(브랜치 `claude/claude-usage-ranking-service-40fe77`)에서 만들고 있는 랭킹 서버가 `main`에 들어온 뒤에 구현한다. 그 작업에는 spec 폴더가 없어서 `Blocked by:` 줄 대신 여기에 적는다.

## 사용자에게 보이는 결과

1. 교육생이 `setup.exe`로 앱을 설치하고, 시작 메뉴에서 연다. Node.js나 bun을 따로 설치하지 않아도 된다.
2. 앱 위쪽 메뉴로 대시보드, 트렌드, 랭킹, 설정을 오간다. 대시보드 머리말에 마지막·다음 업데이트 시각과 랭킹 참여 상태가 보인다.
3. 로그인하지 않으면 지금처럼 PC 안에서만 쓰고, 아무것도 밖으로 보내지 않는다.
4. 로그인하고 닉네임을 정하면 랭킹에 참여한다. 정해 둔 주기마다 PC 화면을 새로 읽고, 날짜별 숫자를 랭킹 서버에 올린다.
5. 창을 닫아도 트레이에 남아 업데이트를 계속한다. 트레이 메뉴의 "종료"로 완전히 끈다.
6. 랭킹 화면에서 지표와 기간을 골라 순위를 보고, 내 값을 평균·1위와 비교한다.
7. 설정에서 업데이트 주기, Windows 시작 시 실행, 닉네임을 바꾸고, 다음에 올라갈 값을 미리 보고, 로그아웃하거나 올린 기록을 모두 지운다.

## 승인된 범위

- Windows x64용 Electron 설치 파일(`setup.exe`). 시작 메뉴 등록과 제거 프로그램 포함.
- 앱 메뉴(대시보드·트렌드·랭킹·설정)와 대시보드 머리말의 업데이트·랭킹 참여 상태
- 트레이 아이콘과 메뉴(열기, 지금 업데이트, 다음 업데이트 시각, 종료), 창을 닫으면 트레이로 숨기기
- 로그인 화면: 이메일·비밀번호 로그인, 가입 링크, 로그인하지 않고 계속, 처음 로그인 시 닉네임 정하기, 올라가는 것과 올라가지 않는 것 안내
- 주기 업데이트: PC 화면 새로 읽기와 로그인 시 랭킹 서버 업로드를 같은 주기로
- 랭킹 화면: 지표별·기간별 순위 표(내 줄 강조), 나와 비교(평균·1위), 업데이트 상태와 지금 업데이트
- 설정 화면: 업데이트 주기, Windows 시작 시 실행, 창을 닫을 때 동작 안내와 트레이 메뉴, 로그인한 계정·로그아웃, 닉네임 변경, 올라가는 값 보기, 내 기록 삭제(확인 대화상자)

## 수용 기준

**설치와 실행**
- AC1. Windows x64 PC에서 `setup.exe`를 실행하면 앱이 설치되고 시작 메뉴에 "My Claude Inspector"가 생긴다. Node.js·bun이 없는 PC에서도 열린다. 제거 프로그램으로 지울 수 있다.
- AC2. 설치한 앱에서 대시보드, 트렌드, 자세히 보기가 지금 웹앱과 같은 값과 동작으로 보인다(claude-status-dashboard의 수용 기준 유지). Claude 설치 경로 기본값은 그 PC 사용자의 `~/.claude`이고, 마지막으로 넣은 프로젝트 경로는 다음 실행 때 다시 채워진다.
- AC3. 앱 위쪽 메뉴로 대시보드, 트렌드, 랭킹, 설정을 오가고, 지금 화면이 메뉴에 표시된다.

**트레이와 주기 업데이트**
- AC4. 창을 닫으면 앱이 끝나지 않고 트레이 아이콘으로 남는다. 트레이 메뉴에 "My Claude Inspector 열기", "지금 업데이트", 다음 업데이트 시각, "종료"가 있다. "종료"를 고르면 앱과 업데이트가 모두 멈춘다.
- AC5. 설정의 업데이트 주기(15분, 30분, 1시간, 3시간, 하루)마다 PC 화면 값을 새로 읽고 그날 스냅샷을 갱신한다. 로그인했다면 같은 때에 랭킹 서버에도 올린다. 대시보드 머리말과 랭킹 화면에 마지막·다음 업데이트 시각이 보인다.
- AC6. "지금 업데이트"(트레이 메뉴, 랭킹 화면)를 누르면 주기를 기다리지 않고 바로 업데이트하고, 다음 업데이트 시각을 그때부터 다시 센다.
- AC7. "Windows를 켤 때 실행"을 켜면 Windows에 로그인할 때 앱이 트레이로 시작하고, 끄면 시작하지 않는다.

**로그인과 참여**
- AC8. 로그인하지 않은 상태에서는 랭킹 서버로 아무것도 보내지 않는다. 대시보드 머리말과 랭킹 화면에 "로그인 안 함 · 이 PC에서만 사용 중"이 보인다.
- AC9. 이메일·비밀번호가 맞으면 로그인되고, 처음 로그인한 계정은 닉네임(2–24자)을 정한 뒤 랭킹에 참여한다. 틀리면 "로그인하지 못했어요"가 보이고 로그인되지 않는다. "가입하기"는 랭킹 서버의 가입 화면을 브라우저로 연다.
- AC10. 앱을 다시 켜도 로그인이 유지된다. 로그아웃하면 그 뒤로는 아무것도 보내지 않고, 랭킹에서 내 줄 강조가 사라진다.
- AC11. 로그인 화면에 올라가는 것(날짜별 숫자 18종)과 올라가지 않는 것(대화 내용, CLAUDE.md·Memory 본문, Skill·MCP·CLI 이름, 프로젝트 이름과 경로, 비밀 값)이 보인다.

**올리는 값**
- AC12. 랭킹 서버에 올리는 값은 날짜별 숫자 18종뿐이다: 입력·출력·캐시 쓰기·캐시 읽기 토큰, 세션 수, 메시지 수, 사용 시간(분), 도구·Skill·MCP·서브에이전트 호출 수, 자동 압축 횟수, `/clear` 횟수, 최대 동시 세션, 최대·평균 컨텍스트 %, 70% 넘은 세션 수. 대화 내용, 파일 본문, Skill·MCP·CLI 이름, 프로젝트 이름·경로, 세션 제목은 보내는 요청 어디에도 들어가지 않는다.
- AC13. 설정의 "올라가는 값 보기"에 다음 업로드에 들어갈 오늘 값이 그대로 보인다.
- AC14. 업로드가 실패하면 PC 화면은 정상적으로 업데이트되고, 랭킹 화면에 "랭킹 서버에 올리지 못했어요"와 다음 재시도 시각이 보인다. 다음 주기나 "지금 업데이트"에서 다시 올리며, 실패한 동안의 날짜도 함께 올라간다.

**랭킹**
- AC15. 랭킹 화면에서 지표(입력+출력 토큰, 세션 수, 사용 시간, 도구 호출, 최대 동시 세션, 70% 넘은 세션)와 기간(오늘, 7일, 30일, 전체)을 고르면 순위 표가 바뀐다. 표에는 순위, 닉네임, 값과 막대, 올린 일수가 있고 내 줄이 강조된다. "70% 넘은 세션"은 적을수록 위다.
- AC16. "나와 비교"는 지표마다 내 값, 참여자 평균, 1위 값과 내 순위(○위 / 참여자 수)를 보여 준다.
- AC17. 로그인하지 않아도 순위 표는 볼 수 있고, "로그인하면 내 순위가 여기에 나와요" 안내와 로그인 링크가 보인다.

**설정과 삭제**
- AC18. 닉네임을 바꾸면 다음 랭킹 표시부터 새 닉네임으로 보인다. 다른 사람이 쓰는 닉네임이면 바꿀 수 없다고 안내한다.
- AC19. "기록 삭제"를 누르면 확인 대화상자가 지울 날짜 수와 되돌릴 수 없다는 점을 보여 준다. "모두 지우기"를 누르면 랭킹 서버에서 내 날짜별 기록이 모두 지워지고 랭킹에서 빠진다. 계정과 PC의 대시보드·스냅샷은 그대로이고, 다음 업로드부터 새로 쌓인다. "취소"를 누르면 아무것도 지우지 않는다.

**경계**
- AC20. 앱은 지금처럼 Claude 설정 파일을 바꾸지 않고, 로그인 정보·토큰·API 키 같은 Claude 쪽 비밀 값을 읽지 않는다. 랭킹 로그인 정보는 그 PC 안에만 저장된다.
- AC21. 앱 창은 넓은 화면, 768px, 390px 폭에서 가로로 넘치지 않는다.

## 확정된 제약과 근거

- **랭킹 서버는 다른 worktree에서 만들고 있는 서버를 그대로 쓴다.** 같은 서버 코드를 두 곳에서 고치면 충돌하기 때문이다. 이 작업은 데스크톱 앱 쪽만 다룬다. (사용자 확정)
- **올리는 값은 서버에 이미 있는 날짜별 숫자 18종뿐이다.** 이름(Skill·MCP·CLI)은 PRODUCT.md가 허용하지만, 랭킹 목적인 사용량 비교에는 숫자로 충분해서 이번에는 올리지 않는다. (사용자 확정)
- **창을 닫으면 트레이에 남아 업데이트를 계속하고, 트레이 메뉴의 "종료"로만 멈춘다.** 수업 중 창을 닫고 다른 일을 해도 랭킹이 최신으로 유지되게 하기 위해서다. (사용자 확정)
- **Windows x64용 Electron 설치 파일로 배포한다.** 지금 앱이 PC 파일을 읽는 Node.js 서버를 함께 실어야 하고, 트레이·백그라운드 실행·시작 시 실행을 기본으로 지원하기 때문이다. 단일 exe는 실행마다 풀어서 느리고 시작 시 실행과 잘 맞지 않는다. (사용자 확정)
  - Electron과 electron-builder에는 공식 에이전트 스킬이나 `llms.txt`가 없다(2026-11-19 확인: skills.sh 검색, electronjs.org·electron.build `llms.txt` 404). 공식 문서는 구현할 때 직접 확인한다. 커뮤니티 스킬 `pedronauck/skills@electron-builder`, `full-stack-skills/electron-skills`는 설치하지 않았다.
- **로그인하지 않으면 아무것도 보내지 않는다.** PRODUCT.md의 "랭킹 참여는 선택" 경계다.

## 가정 (바꿀 수 있음)

- 업데이트 주기 선택지는 15분, 30분, 1시간, 3시간, 하루이고 기본값은 1시간이다.
- "Windows를 켤 때 실행"의 기본값은 꺼짐이다.
- 로그인 계정은 랭킹 서버의 Supabase 이메일·비밀번호 계정이고, 가입은 서버의 가입 화면에서 한다. 앱은 로그인 후 서버가 주는 개인 업로드 토큰으로 올린다.
- 닉네임은 처음 로그인할 때 정한다.
- 로그인하지 않아도 순위 표는 볼 수 있다.
- 기록 삭제는 랭킹 기록만 지우고 계정은 남긴다.
- 랭킹 서버 주소는 앱에 기본값으로 들어 있다.
- 업로드할 때는 최근 30일치 날짜별 값을 다시 보내서, 실패했던 날짜와 하루 중 바뀐 값을 함께 맞춘다.
- 랭킹 지표 칩은 서버 지표 18종 중 6개만 보여 준다. 나머지는 "나와 비교"나 이후 작업에서 다룬다.

## 범위 밖과 이유

- **랭킹 서버 자체의 변경:** 테이블, API, 서버의 `/ranking` 화면은 다른 worktree의 작업이 맡는다. 다만 아래 "Setup before implementation"의 삭제 기능은 그 서버가 갖춰야 한다.
- **이름(Skill·MCP·CLI) 업로드와 이름 기반 랭킹:** 사용자 결정으로 이번에서 뺐다.
- **macOS·Linux 설치 파일, 코드 서명, 자동 업데이트:** 요청되지 않았다.
- **기수·반 나누기:** PRODUCT.md가 나누지 않는다고 정했다.
- **보안 하드닝, 엣지케이스·성능 방어:** AGENTS.md의 검증·리뷰 예산에 따라 범위 밖이다.

## 남은 위험

- **랭킹 서버가 아직 바뀌는 중이다.** 닉네임+비밀값 방식에서 로그인+개인 토큰 방식으로 옮겨 가는 중이라, 구현할 때 서버의 실제 API와 이 spec의 가정(로그인 방식, 토큰, 삭제)을 다시 맞춰 봐야 한다.
- **서명 없는 설치 파일:** Windows SmartScreen이 "알 수 없는 게시자" 경고를 띄운다. 교육생은 "추가 정보 → 실행"을 눌러야 한다.
- **설치 파일 크기:** Chromium과 Node.js가 함께 들어가 150–250MB 정도다. 지금 빌드는 스냅샷 폴더를 읽는 코드 때문에 프로젝트 전체를 서버 출력에 넣으려는 경고가 있어, 정리하지 않으면 더 커진다.
- **PC를 끄거나 앱을 종료한 동안:** 업데이트가 멈춘다. 다음에 켰을 때 최근 30일치를 다시 올려 맞추지만, 그동안 랭킹은 오래된 값이다.
- **Claude 내부 형식:** 사용량 숫자는 Claude Code가 문서화하지 않은 대화 기록 형식에서 계산한다. 업데이트로 바뀌면 올리는 값도 틀어질 수 있다.

## Setup before implementation

- 랭킹 서버가 `main`에 합쳐지고 인터넷에서 접속 가능한 주소에 배포됨 — 앱이 로그인·업로드·순위 조회를 하기 위해 필요 — 완료 조건: 그 주소의 `GET /api/ranking/metrics`가 브라우저에서 지표 목록을 돌려준다.
- 랭킹 서버에 "로그인한 본인의 랭킹 기록 전체 삭제" API가 있음 — AC19의 기록 삭제를 위해 필요 — 완료 조건: 테스트 계정으로 그 API를 직접 호출한 뒤 `GET /api/ranking/leaderboard`에서 그 닉네임이 빠진다.
- 랭킹 서버의 Supabase 프로젝트에서 이메일·비밀번호 로그인이 켜져 있음 — AC9 로그인을 위해 필요 — 완료 조건: 서버의 가입 화면에서 새 테스트 계정을 만들고 로그인할 수 있다.
