# 데스크톱 앱에서 선택형 사용량 랭킹 연동

데스크톱 앱(`docs/specs/desktop-app-download/`)에 랭킹 참여를 더한다. 원하는 사람은 로그인해서, 앱의 업데이트 주기마다 날짜별 사용 숫자를 랭킹 서버에 올리고, 다른 교육생과 순위를 비교하고, 올린 기록을 직접 지울 수 있다.

연결된 자료:
- Blocked by: docs/specs/desktop-app-download/
- [prototype.html](prototype.html) — 승인된 화면. 이 폴더가 따르는 화면과 상태는 다음과 같다.
  - **로그인:** 기본, 로그인 실패, 처음 로그인
  - **랭킹:** 기본, 로그인 안 함, 업로드 실패
  - **설정 화면의 "계정과 랭킹" 카드:** 기본, 삭제 확인, 로그인 안 함
  - **대시보드 머리말의 "랭킹 참여 중" 표시와 앱 메뉴의 "랭킹" 항목**
  - 설치, 트레이, 업데이트 주기, 다운로드 페이지는 desktop-app-download가 따르는 부분이다. 데이터는 모두 예시다.
- [PRODUCT.md](../../../PRODUCT.md) — 랭킹 참여는 선택, 숫자와 이름까지만 올림, 대화 내용·CLAUDE.md·Memory 본문 제외, 비밀 값은 읽지 않음, 본인 삭제, 사용자가 정한 업데이트 주기.
- [ui-composition](../../decisions/ui-composition.md) — 일반 UI는 공식 shadcn component로 구성하고 색은 semantic token으로만 표현한다.
- [desktop-app-download](../desktop-app-download/spec.md) — 설치 앱, 트레이, 업데이트 주기, 앱 메뉴. 이 작업은 그 위에 얹는다.

랭킹 서버는 PR #2로 `main`에 합쳐져 https://myclaudeinspector.vercel.app 에 배포돼 있다(2026-11-19 확인).

## 사용자에게 보이는 결과

1. 로그인하지 않으면 데스크톱 앱이 지금처럼 PC 안에서만 동작하고, 아무것도 밖으로 보내지 않는다.
2. 로그인하고 닉네임을 정하면 랭킹에 참여한다. 앱의 업데이트 주기마다 날짜별 숫자를 랭킹 서버에도 올린다.
3. 앱 메뉴에 "랭킹"이 생긴다. 랭킹 화면에서 지표와 기간을 골라 순위를 보고, 내 값을 평균·1위와 비교한다.
4. 대시보드 머리말과 랭킹 화면에 랭킹 참여 상태와 마지막 업로드 시각이 보인다.
5. 설정에서 닉네임을 바꾸고, 다음에 올라갈 값을 미리 보고, 로그아웃하거나 올린 기록을 모두 지운다.

## 승인된 범위

- 로그인 화면: 이메일·비밀번호 로그인, 가입 링크, 로그인하지 않고 계속, 처음 로그인 시 닉네임 정하기, 올라가는 것과 올라가지 않는 것 안내
- 업데이트 주기마다 하는 랭킹 서버 업로드(로그인했을 때만)
- 앱 메뉴의 "랭킹" 항목과 대시보드 머리말의 랭킹 참여 상태
- 랭킹 화면: 지표별·기간별 순위 표(내 줄 강조), 나와 비교(평균·1위), 업로드 상태와 지금 업데이트
- 설정 화면의 "계정과 랭킹" 카드: 로그인한 계정·로그아웃, 닉네임 변경, 올라가는 값 보기, 내 기록 삭제(확인 대화상자)

## 수용 기준

**로그인과 참여**
- AC1. 로그인하지 않은 상태에서는 랭킹 서버로 아무것도 보내지 않는다. 대시보드 머리말과 랭킹 화면에 "로그인 안 함 · 이 PC에서만 사용 중"이 보인다.
- AC2. 이메일·비밀번호가 맞으면 로그인되고, 처음 로그인한 계정은 닉네임(2–24자)을 정한 뒤 랭킹에 참여한다. 틀리면 "로그인하지 못했어요"가 보이고 로그인되지 않는다. "가입하기"는 랭킹 서버의 가입 화면을 브라우저로 연다.
- AC3. 앱을 다시 켜도 로그인이 유지된다. 로그아웃하면 그 뒤로는 아무것도 보내지 않고, 랭킹에서 내 줄 강조가 사라진다.
- AC4. 로그인 화면에 올라가는 것(날짜별 숫자 18종)과 올라가지 않는 것(대화 내용, CLAUDE.md·Memory 본문, Skill·MCP·CLI 이름, 프로젝트 이름과 경로, 비밀 값)이 보인다.

**올리는 값과 시점**
- AC5. 로그인했다면 앱의 업데이트 주기(desktop-app-download의 주기 업데이트, 트레이·랭킹 화면의 "지금 업데이트" 포함)마다 랭킹 서버에도 올린다. 대시보드 머리말에 "랭킹 참여 중 · 닉네임"이, 랭킹 화면에 마지막·다음 업로드 시각이 보인다.
- AC6. 랭킹 서버에 올리는 값은 날짜별 숫자 18종뿐이다: 입력·출력·캐시 쓰기·캐시 읽기 토큰, 세션 수, 메시지 수, 사용 시간(분), 도구·Skill·MCP·서브에이전트 호출 수, 자동 압축 횟수, `/clear` 횟수, 최대 동시 세션, 최대·평균 컨텍스트 %, 70% 넘은 세션 수. 대화 내용, 파일 본문, Skill·MCP·CLI 이름, 프로젝트 이름·경로, 세션 제목은 보내는 요청 어디에도 들어가지 않는다.
- AC7. 설정의 "올라가는 값 보기"에 다음 업로드에 들어갈 오늘 값이 그대로 보인다.
- AC8. 업로드가 실패하면 PC 화면은 정상적으로 업데이트되고, 랭킹 화면에 "랭킹 서버에 올리지 못했어요"와 다음 재시도 시각이 보인다. 다음 주기나 "지금 업데이트"에서 다시 올리며, 실패한 동안의 날짜도 함께 올라간다.

**랭킹**
- AC9. 랭킹 화면에서 지표(입력+출력 토큰, 세션 수, 사용 시간, 도구 호출, 최대 동시 세션, 70% 넘은 세션)와 기간(오늘, 7일, 30일, 전체)을 고르면 순위 표가 바뀐다. 표에는 순위, 닉네임, 값과 막대, 올린 일수가 있고 내 줄이 강조된다. "70% 넘은 세션"은 적을수록 위다.
- AC10. "나와 비교"는 지표마다 내 값, 참여자 평균, 1위 값과 내 순위(○위 / 참여자 수)를 보여 준다.
- AC11. 로그인하지 않아도 순위 표는 볼 수 있고, "로그인하면 내 순위가 여기에 나와요" 안내와 로그인 링크가 보인다.

**설정과 삭제**
- AC12. 닉네임을 바꾸면 다음 랭킹 표시부터 새 닉네임으로 보인다. 다른 사람이 쓰는 닉네임이면 바꿀 수 없다고 안내한다.
- AC13. "기록 삭제"를 누르면 확인 대화상자가 지울 날짜 수와 되돌릴 수 없다는 점을 보여 준다. "모두 지우기"를 누르면 랭킹 서버에서 내 날짜별 기록이 모두 지워지고 랭킹에서 빠진다. 계정과 PC의 대시보드·스냅샷은 그대로이고, 다음 업로드부터 새로 쌓인다. "취소"를 누르면 아무것도 지우지 않는다.

**경계**
- AC14. 랭킹 로그인 정보는 그 PC 안에만 저장된다. Claude 쪽 비밀 값은 계속 읽지 않는다.
- AC15. 로그인·랭킹·설정 화면은 넓은 화면, 768px, 390px 폭에서 가로로 넘치지 않는다.

## 확정된 제약과 근거

- **랭킹 서버는 PR #2로 합쳐진 서버를 그대로 쓴다.** 같은 서버 코드를 두 곳에서 고치면 충돌하기 때문이다. 이 작업은 데스크톱 앱 쪽만 다룬다. (사용자 확정)
- **올리는 값은 서버에 이미 있는 날짜별 숫자 18종뿐이다.** 이름(Skill·MCP·CLI)은 PRODUCT.md가 허용하지만, 랭킹 목적인 사용량 비교에는 숫자로 충분해서 이번에는 올리지 않는다. (사용자 확정)
- **업로드는 앱의 업데이트 주기에 맞춰 한다.** PRODUCT.md가 "사용자가 정한 주기로 PC 화면과 랭킹 서버를 함께 업데이트"라고 정했다. (사용자 확정)
- **로그인하지 않으면 아무것도 보내지 않는다.** PRODUCT.md의 "랭킹 참여는 선택" 경계다.
- **데스크톱 앱과 내려받기를 먼저 내고, 랭킹 연동은 그 위에 얹는다.** 삭제 API를 기다리는 동안 앱을 먼저 쓰게 하기 위해서다. (사용자 확정)

## 가정 (바꿀 수 있음)

- 로그인 계정은 랭킹 서버의 Supabase 이메일·비밀번호 계정이고, 가입은 서버의 가입 화면에서 한다. 앱은 로그인 후 서버가 주는 개인 업로드 토큰으로 올린다.
- 닉네임은 처음 로그인할 때 정한다.
- 로그인하지 않아도 순위 표는 볼 수 있다.
- 기록 삭제는 랭킹 기록만 지우고 계정은 남긴다.
- 랭킹 서버 주소 기본값은 https://myclaudeinspector.vercel.app 이다.
- 업로드할 때는 최근 30일치 날짜별 값을 다시 보내서, 실패했던 날짜와 하루 중 바뀐 값을 함께 맞춘다.
- 랭킹 지표 칩은 서버 지표 18종 중 6개만 보여 준다.

## 범위 밖과 이유

- **랭킹 서버 자체의 변경:** 테이블, API, 서버의 `/ranking` 화면은 랭킹 서비스 쪽 작업이 맡는다. 다만 아래 "Setup before implementation"의 삭제 기능은 그 서버가 갖춰야 한다.
- **설치 앱, 트레이, 업데이트 주기, 다운로드 페이지:** desktop-app-download가 맡는다.
- **이름(Skill·MCP·CLI) 업로드와 이름 기반 랭킹:** 사용자 결정으로 이번에서 뺐다.
- **기수·반 나누기:** PRODUCT.md가 나누지 않는다고 정했다.
- **보안 하드닝, 엣지케이스·성능 방어:** AGENTS.md의 검증·리뷰 예산에 따라 범위 밖이다.

## 남은 위험

- **랭킹 서버 API와의 차이:** 서버가 닉네임+비밀값 방식에서 로그인+개인 토큰 방식으로 옮겨 왔다. 구현할 때 서버의 실제 API와 이 spec의 가정(로그인 방식, 토큰, 삭제)을 다시 맞춰 봐야 한다.
- **이미 올라간 테스트 기록:** 랭킹에 `테스트A` 같은 기록이 있다. 수업 전에 정리하지 않으면 순위에 함께 보인다.
- **PC를 끄거나 앱을 종료한 동안:** 업로드가 멈춘다. 다음에 켰을 때 최근 30일치를 다시 올려 맞추지만, 그동안 랭킹은 오래된 값이다.
- **Claude 내부 형식:** 사용량 숫자는 Claude Code가 문서화하지 않은 대화 기록 형식에서 계산한다. 업데이트로 바뀌면 올리는 값도 틀어질 수 있다.

## Setup before implementation

- 랭킹 서버에 "로그인한 본인의 랭킹 기록 전체 삭제" API가 있고 배포돼 있음 — AC13의 기록 삭제를 위해 필요 — 완료 조건: 테스트 계정으로 그 API를 직접 호출한 뒤 https://myclaudeinspector.vercel.app/api/ranking/leaderboard 에서 그 닉네임이 빠진다.
